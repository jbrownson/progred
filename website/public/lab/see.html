This is a program. The editor can’t read it yet.

Out of the box, Progred understands four things: records { } (values filed under keys), lists [ ], blobs of raw bytes 0x…, and cells ( ), values with an identity of their own that other places can point to. It has no idea what text is, or a number, or a function, or a picture. Libraries teach it. The words you can already read, like planet, are names this document stores for its own keys, so no library is needed to show them. Each editor below is the same document, shown with one more library loaded. By the bottom of the page it will see a growing forest.

Lesson 1: text

The text library knows one fact: a record whose key is …e5016 and whose value is a blob is a piece of text. Load it, and 0x4d617273 reads as “Mars”. Nothing in the document changed; the editor learned to recognize it.

Try: click “Mars” and type a new name. You’re typing letters; the document stores bytes.

Lesson 2: numbers

The f64 library recognizes eight bytes under its own key, …5d561, as a 64-bit floating-point number, and draws them as 2f64. The small f64 is the library signing its work: it tells you which library read those bytes, and how. There are other number libraries, and they read numbers differently, so the signature matters.

Try: hold Ctrl and drag the 2f64 left and right. You’re holding a number now, not bytes.

Lesson 3: arithmetic, but not running

Here’s a calculation, shown with the same libraries. The f64 library knows its own arithmetic, so it draws 3f64 +f64 2f64, and even the + carries its signature: this is f64’s addition. But the editor can’t run it. The key around it, …f43ee, means “evaluate this” to a library that isn’t loaded yet.

Lesson 4: running things

Grap, Progred’s language, is a library too. It knows that a record under its evaluate key is a calculation to perform, so now the result appears after the arrow and stays current. Even the word “evaluate” comes from Grap; without it the editor only saw an identity.

Try: change the 2f64. The result follows.

Lesson 5: functions

To Grap, a function is a record with a name, a list of parameters, and a body. A call is a record too, and its keys are the function’s parameters: their identities, not their names. Below are three calls and the function they call.

Try: in the recipe, click height and rename it. Every call’s label follows, because each call points at the parameter’s identity, and the name is only a label on it.

Lesson 6: pictures

The layout library knows that calls to fill with a shape are drawing instructions. Load it, and the same calls become trees. The picture is one more way of seeing the same records, and every shape remembers the call that made it. Each shape is data, so the recipe writes it as a template: " keeps it as written, except where ` marks a hole, here the tree’s x and height.

Try: hold Ctrl and click a tree. You land in the code that drew it.

Lesson 7: controls

A few more libraries (sequence, presentation, and controls) and the editor can see the whole forest: a slider feeding a program that plants and grows trees. Same four kinds of value underneath.

Lesson 8: teach it something yourself

Libraries aren’t magic. A view is a function from a value to a drawing, and you can write one in Grap and keep it in the same document as your data. Here’s a planet, a view that draws planets, and the planet drawn by that view.

Try: change moons to 5. Then change the planet’s color in planet drawing. You just taught the editor to see planets.
